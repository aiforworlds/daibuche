# 遥控器（遥控板 V260301）使用手册

> 板子：`SCH_遥控板_V260301` / `BOM_遥控板_V260301`
> MCU：STM32F103C8T6（LQFP48，128KB Flash）
> 本手册最后更新：2026-11-06

---

## 1. 一句话认识这块板

一块 **STM32F103C8T6 + 2.4G 透传模块（JC24B）+ 128×32 OLED + 单轴摇杆** 的电动滑板手持遥控器。

```
Type-C ──► TP4054 充电 ──► 单节锂电 ──► 升压 4.97V ──► AMS1117 ──► 3.3V
                                  └──► TC118S 马达（预留/震动）
```

## 3. 硬件要点（动手前必须知道的四件事）

### 3.1 Type-C 只能充电，不能给系统供电 ⚠

`5V_IN` 网络全部 7 个引脚：USB1 的 VBUS、U8(TP4054) 的 VCC、C18、CN1-2、R16、R21。
**它和 `+5V` / `+3.3V` 之间没有任何通路。** 系统永远由「电池 → 升压 → LDO」供电。

- 所以要烧程序、要看灯亮、要跑程序，**必须插电池并把 SW8 电源开关拨到 ON**。
- 插 USB 只做两件事：充电、点亮白灯 LED6。
- 无电池时靠 TP4054 的泄流也许能亮屏，但一带负载就复位，**不能用来调试**。

### 3.2 烧写口 U6（4 针 1.25mm 座）

| U6 脚 | 信号 | 接 ST-Link 哪个 |
|---|---|---|
| 1 | +5V | **不要接**（ST-Link 的 3.3V 不要往这里灌） |
| 2 | SWCLK / SWDIO | 见下方说明 |
| 3 | SWDIO / SWCLK | 见下方说明 |
| 4 | GND | GND |

> ⚠ 图上 2/3 脚的走线交叉，放大后仍有歧义，**哪一脚是 SWCLK 未最终确认**。
> 实际做法：**只接 3 根线（2、3、4）**，如果连不上就把 2 和 3 对调一次。接反不会烧板，只是连不上。

杜邦线较长时把速度降到 1MHz（下面所有命令都带 `freq=1000`）。

### 3.3 串口口 U2（3 针 1.25mm 座）——没有屏幕时的验证入口

`1 = GND，2 = PA9(TX)，3 = PA10(RX)`，波特率 **115200**，**没有电源脚**（板子自己靠电池）。

随便发一个字符过去，V3.1 固件会走调试分支：**黄灯 LED5 翻转一次**，并回一串 `scaledValue = 0`。

### 3.4 按键与指示灯

**按键**

| 位号 | 接脚 | V2.0 固件功能 | V3.1 固件 |
|---|---|---|---|
| SW4 = KEY_1 | PA4 | 单击：档位 30%→50%→90% 循环；三击：停止模式 | **无按键代码，按了没反应** |
| SW5 = KEY_2 | PA5 | 单击：切换报错信息；三击：清空报错 | 同上 |
| SW4+SW5 | — | 按住 KEY_1 时 KEY_2 三击：正反转 | 同上 |
| SW1 | NRST | 硬件复位 | 有效 |

**指示灯（6 只，全部低电平点亮，LED1 除外）**

| 位号 | 颜色 | 限流 | 控制 |
|---|---|---|---|
| LED1 | 红 | R1 36kΩ | 无，+3.3V→LED→GND，**纯硬件电源灯，常亮（较暗，约 39µA）** |
| LED2 | 黄 | R2 510Ω | PC13 |
| LED3 | 红 | R7 510Ω | PB14（网络名 LED_R） |
| LED4 | 绿 | R12 510Ω | PB15（网络名 LED_G） |
| LED5 | **黄** | R13 510Ω | PB13（网络名 LED_B，实际贴黄灯） |
| LED6 | 白 | R16 1kΩ | TP4054 的 CHRG，插 USB 充电时亮 |

**只亮一颗 LED1 是正常的**，说明 3.3V 域工作正常、程序还没动灯。

### 3.5 BOOT0 / BOOT1 必须接地（本板已改，重要）

**原设计缺陷**：U5 的 `BOOT0`（pin44）和 `PB2/BOOT1`（pin20）只引到测试点 `boot1`、`boot2`，**没有任何下拉电阻**。STM32F1 的 BOOT0 内部无上下拉，悬空时暖复位会被残留电荷锁存为 1。

后果（本板实测复现）：

- **物理断电重启** → 正常，从 Flash 启动
- **任何软件复位**（CubeProgrammer 的 `-rst`、OpenOCD 的 `reset`、按 SW1）→ 有概率锁存 BOOT0=1，改成从 SRAM 启动，执行 ST-Link 下载器残留的向量表 → HardFault → LOCKUP
- LOCKUP 后的表现是"板子彻底死了"，调 `reg pc/reg sp + resume` 也救不回来，**只能拔电池**

**现场判据**（不用示波器，读三个地址就能定性）：

| 地址 | 正常 | 故障 |
|---|---|---|
| `0x00000000`（别名区） | `20004898 08000101`（与 Flash 一致） | `20005000 20000109`（指向 SRAM 的残留向量表） |
| `RCC_CFGR` `0x40021004` | `0x001D840A` | `0x00000000`（一条指令都没跑） |
| `SCB_ICSR` `0xE000ED04` | VECTACTIVE=0（无异常） | `0x803`（VECTACTIVE=3 = HardFault） |
| 复位后 PC | `0x0800xxxx`（Flash） | `0x20000xxx`（SRAM） |

**修复方法**：把测试点 `boot1`（=BOOT0）和 `boot2`（=PB2/BOOT1）都接到 `GND`（直连或 10kΩ 下拉）。焊盘位置见 `原理图/BOOT跳线_测试点位置.png`。

> **本板已于 2026-11-08 完成此改造。** 改造后连续两次软件复位，PC 均稳定落在 `0x08004426 / 0x0800441C`，CFGR=0x001D840A、APB2ENR=0x421D、USART3_BRR=0x753（19200）全部为初始化后的值 —— **烧完不用再拔电池了**。
>
> 以后新做的板子，**BOOT0 到 GND 加一颗 10kΩ 下拉再投板**，别留悬空测试点。

## 4. 编译

### 4.1 编译器说明

这台机器上**没有 Keil、没有 arm-none-eabi-gcc、也没有 clang**。
现在的方案是用 **ziglang**（自带完整 LLVM 后端）做 ARM 裸机交叉编译。

安装（已装过，重装才需要）：

```
python -m pip install ziglang -i https://mirrors.aliyun.com/pypi/simple/
```

> 清华镜像没有这个包，用阿里云。

### 4.2 编译按键测试程序

双击 `烧写工具\编译_按键测试程序.bat`，或手工执行：

```
cd 遥控器\测试程序_按键控制灯

python -m ziglang cc -target thumb-freestanding-eabi -mcpu=cortex_m3 -mthumb -Os ^
  -nostdlib -ffreestanding -fno-builtin ^
  -Wl,-T,stm32f103c8.ld -Wl,-e,Reset_Handler ^
  -o key_led.elf key_led.c
```

几个参数不能省：

| 参数 | 作用 |
|---|---|
| `-target thumb-freestanding-eabi` | 生成裸机 ARM 代码（不带操作系统、不带 libc） |
| `-mcpu=cortex_m3` | **必须用等号**，写成空格会报错 |
| `-nostdlib -ffreestanding` | 不链接标准库，避免引入 `_start` 之类的依赖 |
| `-Wl,-T,stm32f103c8.ld` | 指定链接脚本，把向量表放到 0x08000000 |
| `-Wl,-e,Reset_Handler` | 指定入口 |

产物 316 字节左右。校验 ELF 是否正确，看两个值：入口 `0x0800xxxx`、向量表首项 `0x20005000`（栈顶）。

> 注意：`python -m ziglang objdump` 在这台机器上会因 Program Files 权限报 AccessDenied，
> 想反汇编就把 elf 拷到别处再用系统 objdump，或者用 Python 直接解析 ELF 头。

### 4.3 改测试程序

`key_led.c` 顶部四个宏就是全部可调项：

```c
#define KEY1_PIN   4u    // PA4
#define KEY2_PIN   5u    // PA5
#define LED_R_PIN  14u   // PB14 → LED3 红
#define LED_G_PIN  15u   // PB15 → LED4 绿
```

想让按键「按住亮、松开灭」，把主循环里的翻转换成 `led_set(pin, key_down(pin))`；
想换黄灯（PB13）或 PC13 那颗灯，改宏即可。

## 5. 烧录

### 5.1 前置条件

1. 电池插好，SW8 开关拨到 **ON**（否则必失败，见 6.3）
2. ST-Link 的 SWDIO / SWCLK / GND 接到 U6 的 2 / 3 / 4
3. 关掉 Keil 等占用 SWD 的软件

### 5.2 一键脚本（推荐）

| 想烧什么 | 双击 |
|---|---|
| 按键点灯测试程序 | `烧写工具\烧写_按键测试程序.bat` |
| 遥控固件 V3.1 | `烧写工具\烧写_RC_V3.1.bat` |
| 完整功能 V2.0 | `烧写工具\烧写_RC_V2.0完整版.bat` |
| 只看运行状态（不烧） | `烧写工具\读取运行状态.bat` |

### 5.3 命令行

工具路径：

```
C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe
```

先列调试器，确认 ST-Link 在线：

```
STM32_Programmer_CLI.exe -l
```

擦除 + 写入 + 校验 + 复位（一条搞定）：

```
STM32_Programmer_CLI.exe -c port=SWD freq=1000 -e all -w RC_V3.1.hex -v -rst
```

要烧绝对路径时，**先 cd 到 hex 所在目录再用相对文件名**，中文路径直接塞进参数会让 CLI 解析失败。

正常的输出长这样：

```
ST-LINK    : ...  FW V2J48S7
Voltage    : 3.30V
Device ID  : 0x410
Device name: STM32F103xx medium-density
Flash size : 128 KBytes
Mass erase successfully achieved
Download   : 0.584s
Verify     : Download verified successfully
MCU Reset  : Software reset is performed
```

### 5.4 烧完怎么确认真的在跑（不依赖屏幕）

**别用普通模式连接**，普通模式会复位芯片，读出来全是 0。必须加 `mode=hotplug`：

```
STM32_Programmer_CLI.exe -c port=SWD freq=1000 mode=hotplug ^
  -r32 0x40010C0C 0x04 ^
  -r32 0x4001100C 0x04 ^
  -r32 0xE000E018 0x04
```

| 地址 | 寄存器 | 判读 |
|---|---|---|
| `0x40010C0C` | GPIOB_ODR | bit13/14/15 全为 1（如 `0x0000E808`）= 三颗 RGB 灯都被初始化成熄灭 |
| `0x4001100C` | GPIOC_ODR | bit13 = 1（如 `0x00002000`）= PC13 灯灭 |
| `0xE000E018` | SysTick VAL | **连读三次都不同** = 内核在跑 |

补充：`key_led` 测试程序不初始化 SysTick，所以它的 SysTick 恒为 0，**不代表没跑**，看 GPIOB_ODR 就行（应为 `0x0000C010`，bit14/15=1）。

### 5.5 认板子，别烧错

同一块开发环境里可能插着两块板，先读 UID 确认：

```
STM32_Programmer_CLI.exe -c port=SWD freq=1000 -r32 0x1FFFF7E8 0x0C
```

| 板子 | UID 首字 | Flash |
|---|---|---|
| **遥控板**（这块） | `00600061` | 128KB |
| 最小系统板 | `0671FF37` | 64KB |

### 5.6 恢复遥控固件

```
cd 遥控器\固件
STM32_Programmer_CLI.exe -c port=SWD freq=1000 -e all -w RC_V3.1.hex -v -rst
```

## 6. ST-Link 指示灯

ST-LINK/V2 顶部那颗标着 **COM** 的双色灯表示调试器状态（ST 官方 UM1075 第 4.3 节）：

| 灯态 | 官方含义 | 在本项目里的实际操作对应 |
|---|---|---|
| 红色慢闪 | 正在与 PC 做第一次 USB 枚举 | 刚插上电脑的一两秒，正常 |
| 红色常亮 | 与 PC 通信已建立（枚举结束），但还没和目标通信 | 调试器在，但板子没电 / SWD 线没接 / 接反 → 这时会报 `Unable to get core ID` |
| 红绿交替快闪 | 目标与 PC 正在交换数据 | 正在擦除、写入、校验 → **正常，别拔线** |
| 绿色常亮 | 最后一次通信成功 | 烧写完成，芯片已复位运行 |
| 橙色 | 与目标通信失败 | 接线错 / 没共地 / 开关没开 / 芯片被读保护 |

补充说明：

- 克隆版可能只有一颗双色灯，也可能有 `PWR`（红，常亮=USB 供上电）+ `COM`（双色）两颗，**以丝印为准，含义同上**。
- 灯完全不亮 → 换根 USB 线（有些线只充电不传数据），或驱动没装。
- 灯常红且怎么都不变绿 → 先查电池和开关，再查 SWD 三根线，最后才怀疑片子。

本机实测的调试器信息（换电脑/换线都会变，仅供参考）：

```
ST-LINK SN : B55B5AAE0000000035720700
ST-LINK FW : V2J48S7
Voltage    : 3.30V（电池供上后）
Device ID  : 0x410 / 128KB
UID        : 00600061 59000002 56314C4D
```

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `Unable to get core ID` / `No STM32 target found` | **板子没电**（最常见） | 插电池 + 开关 ON。Type-C 供电救不了它 |
| 同上，电池已插 | SWD 接反 | 把 U6 的 2、3 脚对调 |
| 同上，接线也对 | 没共地 | 补一根 GND |
| 连上但读寄存器全 0 | 用了普通模式连接，芯片被复位 | 加 `mode=hotplug` |
| 烧写报 verify 失败 | 速度太快 / 线太长 | 降 `freq=500` 或 `freq=1000` |
| 烧完没反应，只有一颗暗红灯 | 正常 | 那颗是硬件电源灯 LED1，程序没亮别的灯说明初始化跑完了 |
| **烧完或按复位后板子彻底没反应，拔电池再插又活了** | **BOOT0 悬空被锁存为 1，改从 SRAM 启动进 HardFault 锁死** | 见 **3.5**，把 `boot1`/`boot2` 焊盘焊到 GND，之后永久解决 |
| 按键按了没反应 | 用的是 V3.1，固件里没有按键代码 | 烧 `RC_V2.0_预编译.hex`，或烧 `key_led` 测试程序验证硬件 |
| 绿灯（LED4）不亮 | 它是 JC24B 握手成功指示 | 模块没焊 / 接收端没上电，属预期 |
| 颜色跟代码对不上 | 图纸 PB13=B、PB14=R、PB15=G，固件 GREEN→PB13 | 已知问题，见第 8 节 |
| OLED 不亮 | 屏幕还没焊 / 软件 IIC 写不出去 | 不影响主循环，先不管 |

## 8. 已知问题

1. **RGB 映射错位**：图纸 `PB13=LED_B、PB14=LED_R、PB15=LED_G`，固件 `GREEN→PB13、BLUE→PB14、RED→PB15`，绿红对调；且 LED5（网络名 B 通道）实际贴的是黄色灯珠。
2. **RC_V3.1.hex 的时间戳问题**：该 hex 由 2026-06-03 22:37 的 `.axf` 转换，而 `RC_Cmd.c` 最后一次改动是当天 22:43，**这处改动不在镜像里**。收发异常时先怀疑这个。
3. **`CHRG` 网络名不实**：它实际是「USB 是否插入」（R21 上拉 5V_IN，10k+10k/36k 分压恒得 3.21V），跟 TP4054 的 CHRG 脚没连（那颗只驱动 LED6）。用 PA2 判断充电状态会误判。
4. **VBAT（1 脚）悬空**：手册要求无备份电池时接 VDD，建议飞线到 +3.3V。
5. **PB8/PB9 → TC118S 的 INA/INB 未使用**，马达接口属预留。
6. **U6 的 2/3 脚 SWCLK/SWDIO 对应关系未最终确认**（图上走线交叉），实际以「连不上就对调」处理。

## 9. 一分钟速查

```
【必须做】插电池 + 开关 ON        ← 没有这步什么都别谈
【接线】  U6: 2=SWCLK/SWDIO 3=SWDIO/SWCLK 4=GND，1 脚(+5V) 空着
【编译】  cd 测试程序_按键控制灯 && python -m ziglang cc -target thumb-freestanding-eabi
          -mcpu=cortex_m3 -mthumb -Os -nostdlib -ffreestanding -fno-builtin
          -Wl,-T,stm32f103c8.ld -Wl,-e,Reset_Handler -o key_led.elf key_led.c
【烧写】  STM32_Programmer_CLI -c port=SWD freq=1000 -e all -w xxx.hex -v -rst
```

## 11. 进阶测试：摇杆控制流水灯

### 11.1 摇杆的真实接法（网表逐脚核对，别抱幻想）

| 摇杆脚 | 接到哪 | 状态 |
|---|---|---|
| 4 脚 A | +3.3V | 电位器上端 |
| 6 脚 B | GND | 电位器下端 |
| 5 脚 DTA | `ADC_SEN` → **PA3** | ✅ 唯一能用的模拟轴 |
| 2 脚 DTA | 悬空 | ❌ 第二个轴没接 |
| a / b / c / d、7 / 8 / 9 / 10 | 悬空 | ❌ **中央按动开关没接** |

结论：这块板上的 RKJXV1224005 实际只当一个**单向电位器**用，
中央按下去没有任何电气反应——不是坏了，是画板时就没连。

### 11.2 四个可控灯

| 代号 | 引脚 | 颜色 | 位号 |
|---|---|---|---|
| D0 | PB13 | 黄 | LED5 |
| D1 | PB14 | 红 | LED3 |
| D2 | PB15 | 绿 | LED4 |
| D3 | PC13 | 黄 | LED2 |

LED1 是纯硬件电源灯、LED6 是充电灯，都不归程序管。
亮度用 16 级软件 PWM 实现，所以能做呼吸和调光。

### 11.3 操作方式

| 操作 | 效果 |
|---|---|
| KEY_1 单击 | 切换特效模式（循环） |
| KEY_2 单击 | 暂停 / 继续（画面冻住） |
| 摇杆偏离中位 | 偏离越多动画越快（每步 40 帧 → 4 帧） |
| 摇杆越过中位 | 改变流水方向 |

| 模式 | 名称 | 表现 |
|---|---|---|
| 0 | 光柱 | 摇杆位置直接决定点亮几颗，边界那颗按比例渐变 |
| 1 | 乒乓 | 一个亮点左右来回扫，两端反弹，带拖尾 |
| 2 | 呼吸 | 四颗同步渐亮渐暗 |
| 3 | 追逐 | 两颗灯追着跑 |
| 4 | 交替 | 0/2 与 1/3 两组快速对闪 |
| 5 | 调光 | 摇杆当旋钮，四颗一起由暗到亮 |

**模式 0 是自检模式**：把摇杆从一头推到另一头，4 颗灯应该依次点亮、渐变。
如果模式 0 不动，说明 ADC 那条线有问题，先查这里再怀疑特效代码。

### 11.4 编译与烧写

```
双击  烧写工具\编译_摇杆流水灯.bat
双击  烧写工具\烧写_摇杆流水灯.bat
```

手工命令就是第 4 节那条，只把文件名换成 `joystick_led.c` / `joystick_led.elf`。

恢复遥控固件：`烧写_RC_V3.1.bat`。

### 11.5 可选改造：把中央按动开关接出来

想用上那个按动开关，飞一根线即可（RKJXV 的开关是 a-c 一组、b-d 一组，任选一组）：

```
摇杆 a（或 c）  ──────►  MCU 的 PB0（pin18）
摇杆 对侧脚      ──────►  GND
```

然后把 `joystick_led.c` 里这一行改成 1，重新编译烧写：

```c
#define USE_CENTER_KEY 1
```

改完之后**按住中央键 = 四颗灯全亮**，松开恢复当前特效。

可选脚位（网表确认空闲）：`PB0`、`PB1`、`PB12`、`PA8`、`PA15`、`PA0`、`PA7`、`PA11`、`PA12`。
**不要动 PA13 / PA14**，那是 SWD，占了就连不上烧写器。

### 11.6 摇杆不灵的时候

| 现象 | 原因 / 处理 |
|---|---|
| 只有一个方向有反应 | 正常，第二个轴（2 脚 DTA）本来就没接 |
| 中间位置灯不是 0 颗也不是 4 颗 | 正常，中位约 2.0V，模式 0 会亮 2 颗 |
| 推到底也点不满 4 颗 | 电位器两端压不到 0V/3.3V，正常，属于机械公差 |
| 中位偏一边、轻轻一碰就反向 | 调大 `ADC_DEAD`（默认 250，约 0.2V） |
| 中位明显不是 2048 | 改 `ADC_MID` 为模式 0 里看到的实际中位值 |
| 模式 0 完全没变化 | PA3 虚焊 / 摇杆 DTA 没焊，先量 PA3 电压是否随摇杆变 |
